# Design: Chog Buddy

## Problem Statement
Chogathon asks for a new way to interact with NFTs where the Chog NFT is essential: remove it and the experience breaks. Judging: Novelty 30%, Fun 20%, Retention 20%, Clarity 15%, Execution 15%, $CHOG bonus.

Chog Buddy: your Chog NFT becomes an animated desktop pet (Mac + Windows) that reacts to what you do on your computer, with a personality derived from its traits and a public "soul" written onchain against its token ID.

## What Makes This Cool
- Two Chogs react completely differently to the same afternoon. The NFT's traits are the personality.
- It lives on your screen, so retention is passive: you see it every day without opening anything.
- Private diary stays with the owner; public soul stays with the token. A Chog shaped by months with a night-owl coder is a different creature from a fresh one.
- Prior art (from research): NFT pets (Monagotchi), AI-chat NFTs (OneOnOne), rental platforms exist. None found that combine an OS-level pet, trait-driven personality and a non-strippable onchain soul.

## Constraints
- 14 days, 2 people: one on frontend + backend (owner), one on backend + smart contracts (teammate).
- $0 budget: free tiers only; no code signing.
- Desktop only (Mac + Windows). Phone later.
- Chog Genesis: ERC-721 on Monad mainnet, `0xc96d31F8626c6D03Fae5dCD3d61e3FB9F4a73763`, 1,969 supply, not enumerable. Metadata `ipfs://bafybeid4ybujnscdipkno7ps5utqelp5ry5ryreqhay3zhgk3a6x4jruqu/<n>.json`; token IDs are shuffled against metadata (always resolve via `tokenURI`). Images are flattened 1000x1000 WebP, no trait layers known.
- Trait categories: Background, Aura, Base, Skin, Side, Body, Mouth, Eyes, Head, Accessory, Form, Tier, Naked.
- $CHOG token reportedly `0x350035555E10d9AfAF1566AaebfCeD5BA6C27777` (unverified; verify onchain before use). Self-described no-utility memecoin.
- macOS has no public API to read other apps' notifications. Windows does (UserNotificationListener, with permission).

## Premises (agreed)
1. Judges will install a desktop app if setup takes under 2 minutes and instructions are excellent.
2. Personality quality (writing, variety, timing) matters more than the number of tracked signals.
3. No web fallback. Accepted risk: a judge who cannot install sees nothing. Mitigation is installer polish and a judge mode.
4. The pet ships first (days 1-8). Focus bets and Chog Park start only once the pet works.

## Decisions
- **LLM:** templated reactions per personality archetype for frequent lines (no API cost, offline-safe); Gemini Flash free tier, via our server, for personality generation and the daily diary.
- **Signing:** ship unsigned installers with clear Gatekeeper/SmartScreen bypass steps and a GIF, first in testing instructions.
- **Presence:** ~120px sprite walks along the Dock/taskbar edge, perches on the active window's title bar, can be dragged and thrown.
- **Interaction:** click to pet, small chat box, focus mode (Chog scolds you on distracting apps/sites).
- **Animation:** superseded by "Pet visuals: pixel sprite kit" below (2026-10-08). The original plan animated the flat NFT image; the shipped v0 did that and it read as a floating picture, not a character.
- **Ownership:** SIWE in a browser popup; server checks ownership (Alchemy NFT API free tier on Monad, fallback `ownerOf` via public RPC). Re-check daily. If the Chog was sold, the pet leaves and the local diary is wiped.
- **Multiple Chogs:** one active pet, swappable from the tray menu. Only the active Chog's soul drifts.
- **Activity data:** app names + durations by default; window titles opt-in. Titles are categorized locally (coding / design / chat / browsing / video / meeting). Only categories and durations leave the machine.
- **Integrations (v1):** GitHub notifications, Google Calendar. Windows system notifications deferred (see Platform notes). Gmail only if time allows. No Discord (no unread API for user accounts). Never read message content.
- **Diary:** generated by the server, stored only on the user's machine, never persisted server-side.
- **Soul:** four axes 0-100 (Night Owl/Early Bird, Grinder/Slacker, Social/Hermit, Creator/Consumer). Base values from traits; max ±3 drift per day. Plus level and owner count. Stored in a `ChogSoul` contract on Monad testnet (decided 2026-10-09), written daily by a server wallet so users pay no gas.
- **XP/level:** days alive with an owner + focus streaks. Unlocks animations/reactions. Not purchasable.
- **Judge mode:** a labeled demo option that loads a fixed Chog read-only (no soul writes) for judges without a Chog.
- **Backend:** Next.js on Vercel free tier + Neon Postgres free. Hosts SIWE, LLM proxy, ownership check, daily soul cron, (later) settlement oracle and Chog Park.
- **App:** Electron.

## Pet visuals: pixel sprite kit (decided 2026-10-08)
Problem: every Chog NFT is a tightly cropped three-quarter bust (head runs off the top/right edge, body cut at the collar), so neither a background cut-out nor a 3D reconstruction gives a whole, walkable character. A trial 3D build (img2threejs) and a trial pixel build with invented faces were both rejected: the 3D could not be judged against a cropped bust, and invented eyes did not look like the owner's Chog.

Decision: a **2D pixel Chog assembled from a shared body kit plus the real NFT face**, packed as a **Petdex/Codex-format sprite atlas**.
- **Body kit (one kit, animated once):** pixel parts drawn in code at 48x52 logical px, scaled 4x nearest-neighbour to the 192x208 frame. Parts: round head shell, gill spikes (3 per side), torso/outfit, arms, legs/feet, hat. Animation is by part offsets per frame (bob, leg swing, arm swing, squash), so every Chog gets every animation for free.
- **Trait-driven parts:** Skin trait -> spike colour; Body trait -> outfit style + colour (keyword map to a few styles: suit, shirt, hoodie, robe, bare); Head trait -> hat shape (keyword map: cap, bucket, wizard, horns, headband, crown, none) with colour sampled from the NFT; Base Skull/Radioactive -> alternate head shell palette.
- **Real NFT face:** crop the face region of the NFT image (inside the frame edges, so never sliced), quantize to a small palette, scale to the head's face window and paste it on the head. Eyes, blush, lasers and expression are the owner's real art. Side=Left mirrors. Back-facing frames show head shell + hat only.
- **Atlas format (Petdex/Codex compatible):** 8 columns x 9 rows of 192x208 frames (1536x1872 PNG). Rows used by Sato: 0 idle (6 frames), 1 walk east (8), 2 walk west (8), 3 react (4), 4 hop (5), 8 celebrate (6). Rows 5-7 are ours: 5 sleep, 6 talk, 7 sad. Exact Petdex metadata format to be verified against petdex.dev before publishing.
- **Where it runs:** pure pixel logic (palette sampling, quantize, kit drawing, compositing) in `@chog/core` on raw RGBA buffers, unit-tested; image decode/encode via the Electron renderer canvas. The atlas is generated once per Chog and cached in userData.
- **Doze/sleep (borrowed from Sato):** when the owner is idle 2+ minutes the Pet stops walking and plays sleep; after 15 minutes idle, animation and polling pause until input returns.
- **Bonus:** "Export for Codex/Petdex" saves the atlas so the same Chog runs in other pet apps.
- 3D is dropped for the hackathon.

## Pet visuals v2: canonical Chog + skins (decided 2026-10-09, details 2026-10-14)
Supersedes the "real NFT face on a body kit" look above. The pasted NFT faces read poorly at pet size, and official Chog art now gives a full-body reference: a purple spiky hood framing a cream face, pink blush, pink nose and pink hands, a purple body suit, and swappable outfits (helmet, hoodie, jacket, dress).
- **One uniform, hand-designed 2D Chog**, drawn from the official art, plugged into the existing sprite/atlas system (same 9 animation rows, same Petdex geometry).
- **Skins** are layers on that body: a default purple suit plus outfit skins (hoodie, jacket, dress).
- **"Your NFT skin"**: the owner's Chog NFT traits pick hat, outfit and colours. This is the "use your own traits" feature.
- **NFT stays essential**: no Chog NFT means no Pet (Judge Mode is labelled demo); the NFT skin is exclusive to its owner; Soul, personality and growth stay bound to the token ID.
- 3D (img2threejs) is a stretch goal only, after the 2D version ships.
- Decided 2026-10-14 (ADR 0005): pixel style; skins Classic/Hoodie/Jacket/Dress/My NFT skin; NFT skin = Body→outfit, Head→hat, colours sampled from the NFT image.

## Mechanics (v1 defaults, tune during build)
- **Archetypes:** 5 archetypes derived from traits (e.g. Hype, Grump, Lazy Sage, Chaos, Sweetheart). Mapping lives in a JSON table `traits -> archetype + base axes` (e.g. `Eyes=Sleepy -> NightOwl +20`). Gemini later adds flavor text per token, cached once per token.
- **Reactions:** ~10 triggers (app switch to category, long session 90m+, idle return, late night, meeting soon, GitHub notification, focus-mode violation, pet click, morning greeting, end of day) x 3 lines per archetype. Minimum 3 minutes between unprompted lines.
- **Categorizer:** local JSON map of app names / title keywords to categories.
- **Drift formula:** the client POSTs daily category totals (minutes) for the active token. The server keeps only per-token aggregates. Each axis moves by clamp(round(raw), -3, +3) per day, then is clamped to 0-100. Source of truth is `driftAxes` in `packages/core/src/soul.ts` (soul-backend plan, Task 3):
  - NightOwl: (late - early) / 60, where late = active minutes 22:00-03:59 local and early = active minutes 05:00-07:59 local.
  - Grinder: (coding + design + meeting - video - idle) / 60.
  - Social: (chat + meeting - 60) / 30, so under an hour of chat+meeting drifts it down.
  - Creator: (coding + design - browsing - video) / 60.
  - Day = Owner-local date. After local midnight the app sends a final upload of the previous day and keeps it until that upload succeeds.
- **Level:** counts days on which the token was the active pet, plus a bonus for focus streaks.
- **Contract:** `ChogSoul.batchSet(uint256[] ids, Soul[] souls)` callable by one writer key (testnet-only key in Vercel env). `Soul` struct: 4 axes, level, ownerCount.
- **Known limit:** if two midnights pass before an upload succeeds, the older day is dropped, because the backend only accepts the last 2 days.
- **Cron:** Vercel daily cron, with a GitHub Actions scheduled workflow as backup trigger. One batched tx per day. Applies only days at least 2 UTC days old, so an Owner in any timezone has finished the day; Souls show a day's Activity about 2 days later.

## API (v1)
`POST /api/auth/nonce`, `POST /api/auth/verify` (SIWE), `GET /api/me/chogs` (ownerOf check), `GET /api/chog/:id` (metadata + cached image proxy), `POST /api/activity` (daily category totals), `POST /api/diary` (returns text, not stored), `POST /api/cron/soul` (auth by secret).

## Platform notes
- **Window:** a small sprite window moved across the screen, not a full-screen overlay. Mac: `setAlwaysOnTop('screen-saver')`, `visibleOnAllWorkspaces`; it hides over fullscreen apps. Test both OSes by day 2.
- **Active app:** the `get-windows` library provides app name and bounds (used for perching). On Mac, window titles need Screen Recording permission; v1 uses app names only, titles opt-in.
- **SIWE return path:** the browser posts the signature to a loopback `http://127.0.0.1:<port>` server inside the app. Judge mode skips SIWE.
- **Ownership check** runs on app launch and daily. If the token is no longer owned, wipe the local diary and dismiss the pet.
- **Unsigned Mac app:** macOS 15+ bypass is System Settings > Privacy & Security > Open Anyway; document `xattr -dr com.apple.quarantine` as a fallback. Ship arm64 and x64 builds.
- **Windows notifications:** UserNotificationListener needs package identity (MSIX). Plain `.exe` can't use it, so this is deferred unless MSIX packaging is quick.
- **Gemini free tier** may use data for training. Only categories and durations are sent, never titles or content. Template diary is the fallback on quota errors.
- **Failure modes:** server offline means the pet runs on local templates and queues activity totals. 0 Chogs means only judge mode is offered.
- **Judge mode:** loads the team's own demo Chog read-only. The team runs that Chog for real, so its soul visibly changes.

## Later phase (only after the pet works)
- **Focus bets ($CHOG):** daily global pool contract (`FocusPool`). Stake on a focus goal; server oracle settles once per UTC day (winner list or Merkle root); winners claim. 10% of lost stakes burned, rest to winners. Anti-cheat: small stake cap, only time with real input counts, random "poke" checks (click within 60s). Honestly labeled as fun anti-cheat, not security. Optional bet type: "ship a GitHub commit today". Testnet + mock $CHOG for demo.
- **Chog Park:** web grid of active Chogs with soul axes, level, public mood line, daily focus leaderboard, link to soul contract entry. No diary content.
- **Stretch:** Chog visits (pet walks to a friend's desktop), $CHOG tips, Chog FC integration (pet "trains" from real productivity).

## Success Criteria
- A judge with a Chog goes from download to pet-on-screen in under 2 minutes.
- Two different Chogs produce visibly different reactions to the same activity.
- Soul values for the demo Chog are readable on a block explorer and change about 2 days after use (cron lag).
- Pet runs a full day without crashing on both Mac and Windows.
- Submission includes demo video (max 3 min), repo, testing instructions, and early user feedback.
